The blueprint

The whole cell, designed end to end

My V3.1 implementation specification turns the lab into a buildable, verifiable system. It is the core work of an AI solutions engineer: evaluate solution approaches, record the decisions, and define how a concept is validated and handed over.

MADSci executes. sdl_dt thinks. Agents assist. ROS 2 moves. The safety system protects.
  • 20 architecture decisions, each with the question, the decision and why
  • 10-stage pipeline with a formulation compiler, CP-SAT scheduling, static and dynamic twin validation, and a per-action execution gate
  • Agentic layer: five LangGraph agents behind one MCP tool server and a LiteLLM gateway (local Ollama models for zero-cost prototyping), with evaluation-gated CI. No tool reaches hardware, approvals or safety configuration.
  • Delivery: 18 acceptance tests, 7 commissioning and safety gates, a 6-milestone roadmap

Engineering agent

Razi: doubt, measure, record

You ask a design question in plain English. Razi runs the twin, searches for better layouts, checks the results against our written requirements and writes a short memo. It is designed so that its safety does not depend on the model behaving well.

1
Razi proposesunderstands the question, decides what to try next, like a junior engineer
2
The twin measuresevery number in a report comes from a simulation result, with units
3
Rules deciderequirements as executable checks, e.g. arm clearance ≥ 8 mm; must blocks, should warns
4
A person approvesrelease needs a typed confirmation code; the agent has no approval tool

The layout is not the lever. I expected to optimize the layout. The evidence pointed to a gripper design change and a dispensing process change instead. It moved the engineering decision to the right place, with a trace. And Razi flagged its own uncertainty: the twin uses box geometry, so some clashes may be artefacts.

Two-speed evaluation

A 6-second screen (reach, room at key poses) and a 14-minute full-loop check, cached by layout fingerprint. Thousands of candidates in the optimizer's model, about 17 screened, 1–3 fully checked.

Optimizer without the LLM

A Gaussian-process Bayesian optimizer (ARD kernel, expected improvement) runs alone and calls the agent back only when the target is met, the budget is spent, progress stalls or nothing works.

One tool layer, no side door

The same 12 tools serve the engineer's CLI, the Claude agent and any MCP client. Adding a new front end, such as an IDE or a Copilot, does not change the safety story.

Physics-informed ML on real hardware

Automated test rigs that turn signals into decisions

Before the agents came the instruments: self-driving test rigs where sensing, modeling and uncertainty had to be right.

AutoVisco: robotic viscometry

Reframed viscosity measurement as inference on the torque trace of a descending spindle: a lubrication-theory model, AIC/BIC model selection, bootstrap uncertainty, and contact detection by anomaly detection.

  • 6 chemistries, 1–125,000 cP, one calibration
  • 18 samples in 5 h, under 7% human time

HTD/PA: dissolution & permeation

Co-developed a parallel transport-testing platform: CFD (Ansys Fluent) and NVIDIA Warp FE models for design, a 4-channel 20 Hz sensor network, and an ML-ready data schema linking every condition to its results.

  • 8 cells in parallel from one pump
  • median CV 3–8%, R² > 0.97

Formulator-Pen: viscous dispensing

A modular dispenser for viscous liquids on a tool-changing CNC. Four designs benchmarked; a density bias diagnosed and calibrated out; film retention identified as the residual error.

How I start in a new team

Days 1–30 · Listen & map

Meet internal customers across domains, rank pain points by time × frequency × feasibility, learn the PLM, requirements, CAE and LLM platforms, and ship one small assistant to build trust.

Days 31–60 · Prove

One or two PoCs, each with a named internal customer and a metric. Build the evaluation set first, then demo weekly.

Days 61–90 · Pilot & platform

Pilot with real engineers, measure, write the go/no-go, and keep the reusable pieces (MCP tool layer, eval harness, audit log) so the next PoC starts faster.
